# 源码职责边界

维护时按调用链和数据所有权定位代码，不以固定行数作为拆分标准。

| 文件 | 职责 |
| --- | --- |
| `src/output/evaluation_logger.cpp` | 日志生命周期、线程互斥、事件策略与写入调度 |
| `src/output/evaluation_csv.cpp` | CSV 表头、列顺序、精度、转义及数据序列化 |
| `src/output/evaluation_summary.cpp` | 汇总计数、预热筛选、分位数与 JSON 汇总 |
| `src/loop/loop_verifier.cpp` | 输入检查、初值调度、最终几何验收和图约束结果 |
| `src/loop/loop_alignment.cpp` | GICP 预处理与缓存、多初值求解、评分和候选比较 |
| `src/output/colored_cloud_writer.cpp` | 原始彩色扫描的追加归档、索引、原始 PCD 导出 |
| `src/output/optimized_colored_export.cpp` | 依据后端关键帧修正导出优化 PCD 和预览变换 |

`evaluation_format.hpp` 和 `loop_alignment.hpp` 是 `src/` 内部协作接口，
不安装为公共头文件。格式模块不拥有日志文件或互斥锁，日志对象仍负责同步；
优化导出继续遵守归档前缀快照和原有锁顺序。

修改 CSV 时同时检查精简、详细两种格式；修改回环求解时同时检查缓存复用、
多初值选择和拒绝条件。拆分文件本身不构成算法改进或数据精度验证。

## 估计与坐标输出约定

后端统一优化六自由度，首节点固定；不添加来自前端姿态的额外倾斜先验。
`BackendManager::observeOdometryQuality` 接收前端实际使用的几何信息，转换到
统一坐标后，按关键帧区间平均协方差形状的质量惩罚。边的信息强度限制在标称
里程计信息的 1% 到 100%，不会因相关扫描数量增加而累加置信度。这是保守的
质量降权，不是完成了时序相关性传播的相对位姿协方差。

回环使用六维几何信息并在测量取逆时变换扰动坐标，保留旋转与平移耦合。
局部精修额外检查远距离竞争解；若竞争解具有更多支持且全源点截断损失更低，
则拒绝歧义匹配。此检查不能替代多关键帧确认，也不保证消除所有结构别名。

默认 TF 链为 `map -> odom -> imu -> lidar`。前端里程计、原始轨迹、局部地图、
原始点云预览和着色预览使用 `odom`；优化关键帧轨迹及重建地图使用 `map`。
`map -> odom` 来自同一后端快照中最后关键帧的优化与原始位姿之比；
`imu -> lidar` 使用固定标定。后端不会直接跳变前端状态或改写局部 IKD 地图。
Odometry 的线速度按消息约定表达在子坐标系 `imu` 中。

图像同步根据传感器时间水位推进：图像时间戳超过扫描匹配范围和乱序余量后，
才判定该扫描缺少图像。`camera.sync_wait_sec` 是时间戳乱序余量，不再作为
墙钟传输延迟限制。图像到达事件唤醒工作线程，避免每个缺失帧串行等待。
帧保留与图像匹配共用 128 帧的有界预算，停机时排空；预算耗尽仍明确报错，
不会宣称支持无限延迟。图像匹配缺失、投影为空和归档任务丢弃分别计数。
