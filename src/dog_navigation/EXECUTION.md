# 导航执行与验证边界

核心算法为 C++17；跟踪与时间参数化在 `src/local_planner/`，决策与安全仲裁在
`src/decision/`，执行节点 ROS 接入在 `src/execution/`，规划节点 ROS 接入在 `src/ros/`。
完整目录与配置对应关系见 [README.md](README.md)。速度与到点容差在 `local_planner.yaml`，
任务超时和恢复重试在 `decision.yaml`，硬件许可及机身接地偏移在 `execution.yaml`。

| 模块 | 职责 |
| --- | --- |
| `timed_trajectory.cpp` | 已验证地形边上的梯形速度、加速度和时间参数，不抄近路 |
| `path_tracker.cpp` | odom 系反馈跟踪、停车转向、低速前进上下楼、平台出口与到点确认 |
| `task_supervisor.cpp` | 任务状态、暂停、取消、有限重试、恢复超时和无进展退出 |
| `safety_arbiter.cpp` | 手动优先、任务撤权、租约、急停门控 |
| `executor_inputs.cpp` | 原子路线校验、连续 odom 位姿、定位修正跳变处理 |
| `executor_tick.cpp` | 编排核心算法与 Walk 步态请求，不直接发底盘速度 |
| `executor_output.cpp` | Action 反馈、名义时间轨迹、短时运动许可 |
| `guard_checks.cpp` | 独立检查状态、定位、路线、TF、实际矩形足迹和制动包络 |
| `dog_web/navigation_bridge.cpp` | HTTP 到 Action/任务服务适配，不承担控制算法 |

任务编排使用显式有限状态机；当前职责不需要引入额外行为树框架。
`terrain_route_validation.cpp` 独立复核旧图边的前进姿态、转向和更细支撑采样，
不通过的连接不得进入执行缓存；有限次重搜索失败会明确返回阻塞。

数据链：`/navigate_terrain` → `/navigation/planner_goal` →
`/local_navigation/terrain_route` → `/navigation/command` →
独立 `velocity_guard` → `/dog/safe_cmd_vel` → 驱动。
`/cmd_vel` 为手动输入，优先于自主任务；接管后旧任务不能自动恢复。
手动控制支持无地图建图，因此不进行地图碰撞认证。驱动自身指令超时停车仍保留。

路线包绑定地图项目、revision、目标时间戳、点、地形节点 ID、楼梯标记和障碍，
避免把不同周期的 Path 和 JSON 状态拼起来执行。缓存路线每帧重新检查当前障碍，
首次复杂搜索超预算时不允许运动，下一次使用已重验证的缓存。

任务服务：`/navigation_executor/pause`、`resume`、`cancel`（Trigger）。
Web 取消会先撤销手动租约并发布零速度，再并行请求 `/velocity_guard/cancel`、执行器取消和规划器取消。
守护节点立即发布零速度并撤销旧任务，执行器立即撤销许可、结束 Action、请求清除规划目标；
旧任务许可和取消前创建的带时间戳目标不能使任务重新开始。接口回执表示停车指令已发出，
实际停止仍须检查新鲜速度反馈。任务终态原因与最近拦截原因保留在状态中。
急停：`/velocity_guard/estop`（SetBool）；解除需新鲜速度反馈且已停车，旧任务仍撤权。
每条自主指令最多存活 0.15s；守护进程 50Hz、执行器 20Hz。
定位、路线、扫描或反馈过期时撤销自主许可，输入恢复超时20s退出，无进展30s退出。

楼梯使用机器人已有 WALK，不增加未经 SDK 证明的楼梯模式：入口停车、对齐、
低速前进、平台停车转向、出口确认。当前按每条地形边停车，速度保守、耗时较长；
这是首版闭环，不能据此宣称已达到连续高效的实机楼梯导航。

统一启动仍用 `dog_bringup` 的 navigation 模式；独立入口：

```bash
source install/setup.bash
ros2 launch dog_navigation execution.launch.py map_root:=$PWD/data/maps map_id:=route_rect_final_r015
```

执行许可由 `execute`、`allow_autonomous` 与 `calibration_confirmed` 共同控制，当前值须以启动配置和运行状态为准。
未取得许可时 Web 只显示状态，不会放行自主运动。平台 base_link 接地偏移已按确认值配置为 0.40m；0.3m 腹部高度及制动参数仍需核实，
不能用0.5m整机总高替代这些量。代码中的加减速度约束是软件假设，未证明实机制动性能。
当前脚下参考点按 `p_ground = p_base + R_base * (0,0,-base_ground_offset)` 计算；
固定偏移是站姿近似，不等于四足接触估计。起点会单独检查实际位置的支撑与机身包络，
不能用附近可通行节点吸附成功代替实际脚下支撑成立。

Web 参数设置中的“自主导航速度与加速度”写入 `map_root/.navigation-motion.json`，
覆盖下一次启动执行器的六项速度/加速度参数，不修改 YAML 或执行许可。页面分别显示保存值与当前运行值；
保存后须重启导航服务，任务运行中不会热更新。安全仲裁启动时读取同一文件，制动减速度取
原保守值与保存的加减速度中的较小值（线性 0.15、角向 0.50），不因提高加速度而缩短制动包络。
BPX 直线起步与持续行走使用 0.21 m/s 避开 0.20 死区，纯旋转使用 0.21 rad/s 起步；
行走时允许低于此值的角速度修正，避免细小方向误差被放大。起停跨死区的
指令跳变属于显式例外，不代表实机加速度已经满足设定值。仅合并同地形标记的严格三维共线点，
不跳过真实拐角或地形变化；短段仍需通过制动包络检查，不能为满足最小速度而绕过仲裁。
参考 Nav2 Humble Regulated Pure Pursuit 的前视点与曲率控制：
普通地面在 `lookahead_distance` 范围内连续跟踪，同地形的小弯折不再逐节点停车；
曲率限制线速度，保持角速度与加速度约束。`continuous_turn_angle` 以上的急转弯及
所有楼梯边界仍先停稳再转向。前视点只作用于跟踪目标，不修改地形高度、路径连通关系或碰撞地图；
实际指令仍须经过执行器的预测碰撞检查与仲裁的完整制动包络检查。
控制器先用保守制动包络约束目标速度，再执行加速度平滑，避免只靠仲裁对过高速度反复发零。
候选同时认证原始指令和保留 12% 速度余量的轨迹，再细化可行速度边界；
转弯轨迹经速度缩放后并不包含原轨迹，不能只检查放大后的曲线。
不能给出低于 0.21 m/s 的非零平移指令。
若平滑后的指令无法认证，则在下一控制周期的加速度可达范围内检查其他前进、横移和转向组合；
没有可认证指令才停车，独立仲裁继续复核期望速度与实际动量。
普通地形行走允许不超过 0.25 m/s 的横移修正（参考 `../dog_ws` 普通地面配置），
沿已认证线段行走并同时转动机身，减少纯前进控制切入弯内侧的问题。
普通地形按前视曲率提前降低平移速度，机身朝向使用独立的 2 倍误差反馈，
减速不再同比削弱转向能力；仍同时检查 XY 与 yaw 的刹停扫掠。
机身旋转时按 `v_command = v_desired - tau * yaw_rate * J * v_desired` 补偿 XY 响应滞后，
随后再执行向量加速度和碰撞约束。`tau = 0.20 s` 是当前录制前向响应的一阶近似；
侧向响应尚未独立辨识，不能据此宣称实机完成标定。离线回归覆盖 0.1～0.3 s 被控对象响应。
楼梯及相邻楼梯边界禁用横移。0.21 m/s 下限作用于 XY 合速度，
移动期间按 XY 速度向量的变化限制加速度；输出仍只有 XY 与 yaw，不发送 Z 速度。
向量加速与转向共同使用加速度预算；直接投影进入最小速度死区时，沿最小速度圆与可达加速度圆的交集调整。
滚动路线裁掉已通过的转角后，当前普通地形段仍保留 XY 控制，不因节点数量变化退回纯前进控制。
普通地形允许跨越最多 12 个图节点、最长 2 m 的候选直连，逐段复核地形支撑、
机身扫掠、端点转向和实时障碍；楼梯边界不跨越。直连对原折线的偏离不超过一地图栅格，
保留搜索选出的转弯走廊。节点候选的修整预算为 100 ms，其他首次修整预算为 20 ms，
仍受总规划预算约束。每条路线只修整一次，缓存刷新复核碰撞与障碍，不反复简化并累积偏移。
已认证直连可从中间位置复用，每帧重新检查实时障碍。它不要求机械狗逐节点沿静态全局折线行走，也不是完整的 DWA 局部控制器。
直连修整保留转角中间节点，避免把多个缓弯合并成必须停车的大转角。
路线刷新先按实际位置关联新路线段，共享终点不能使跟踪器跳到尚未到达的下一段。
原地对齐采用 2 倍航向误差比例反馈，仍受保存的最大角速度、角加速度和起步阈值约束。
原地转向在入口确认停止后保持该状态，不用每帧底盘横摆速度重新开关转向。
速度平滑使用上一条指令作为加速度约束起点，机器人反馈仍用于任务进展、停止确认与安全检查；
取消、急停、过期和碰撞等安全停车不经过缓降。
网页保存的最大线速度、角速度同时约束执行器和仲裁，不再另外固定截为 0.30 m/s。
行走中的对齐状态采用迟滞，避免航向误差在阈值附近反复启停。同一路径刷新保持版本；
同一目标的路径切换只允许原指令在原有效期内交接，并使用新路径及新障碍检查碰撞。
无效路径、指令过期、目标变更和取消任务均不能继承旧指令。
重复或乱序的同任务指令不能延长或撤销已接收指令的有效期。定位修正与已安装轨迹的
map/odom 变换比较，累计小修正超过阈值也须停车重规划。

制动检查分别覆盖期望速度与反馈速度，避免零平移指令漏掉机器人尚存的平移动量。
模型包含 0.15 s 反应时间与独立线性、角向减速，沿转弯轨迹分段检查矩形机身、地形支撑和动态障碍。
轨迹按 0.02 s 数值积分、0.08 m / 0.06 rad 输出检查段；它是离散近似，不能代替实机制动标定。
检查超时停止放行，安全停车仍直接发零，不受正常行走的平滑约束。
矩形地图的实时障碍检查也使用带间隙的 0.66 × 0.58 m 机身，不以外接圆强制判定直行碰撞。
转向扫掠按不超过 0.06 rad 分段，每段以角点最大位移扩张中间朝向矩形，覆盖中间姿态；
旧圆柱地图仍保留圆柱模型。规划与仲裁使用同一几何函数。

参考实现与配置说明：
https://api.nav2.org/nav2-humble/html/regulated__pure__pursuit__controller_8cpp_source.html
https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/configuring_velocity_smoother/
此处借鉴控制机制，未接入 Nav2 插件或将三维地形转换为二维 costmap。

实时规划在障碍分类、图搜索、启发式重建及路径几何认证中检查
`processing_budget`（默认 0.4 s）。超预算返回 `planning_budget_exceeded` 并停车；
这不代表已证明无路，不会写入静态无路缓存。保留已完成的静态转弯认证缓存供重试使用，
每次重新检查当前动态障碍。单次几何检查仍是不可抢占的，预算不是硬实时保证。
下一任务的目标等待上一任务的规划取消回执后再发布，避免迟到的取消清除新目标。
先用静态候选路线逐边检查实时障碍，候选受阻再搜索绕行，避免为软避障代价反复搜索整图。
这优先返回可执行路线，不保证当前障碍代价下的最优解。短暂路线租约缺口会停车，
但须连续阻塞满重试间隔才重新发布目标，避免不断清除已有规划进度。
优先使用权重 2 的节点 Weighted A* 生成绕行候选，再修整和逐段认证所有转角；
候选失败的出边仅在本帧候选搜索中避开，不永久屏蔽其他朝向的合法到达。
末次保留含转向状态和原软代价的搜索。动态转向结果仅在当前障碍帧内缓存，不跨帧继承。
若临时候选禁边使快速搜索耗尽，必须继续末次含转向状态的搜索，不能据此断言无路。
障碍记忆使用逐体素 DDA 射线遍历，避免固定步长采样跳过射线掠过的短体素区间。
仅有正向自由射线证据才清除旧障碍；遮挡或没有扫描不会自动释放占据空间。
执行状态保留 `planner_block_reason`，网页区分通路阻断、端点占据和绕障搜索超时。

网页蓝线订阅 `/local_navigation/global_path`，绿线订阅 `/local_navigation/local_path`。
后者是当前已校验全局路径的前方 `local_length` 范围（包含边界后的完整一条边）；
不是独立优化的局部轨迹。只显示同一任务、目标、地图、规划时间戳且未过期的路径；
浏览器扣除请求耗时，迟到的响应不能延长路径显示有效期。
空路径、取消、失效及地图切换清除显示。路径的高度保留用于地形显示，速度指令仍只含 XY/yaw。

验证区分：纯算法测试、真实地图理想速度反馈、隔离 DDS 节点测试、实机。
前三项不能覆盖机身俯仰、四足落点、脚滑、下楼制动和动态人体漏检；
机器人未连接时不能完成实机闭环、制动距离或楼梯通过率验证。
