# 导航性能测量与优化

目标是减少已测量的重复计算，同时保持几何、支撑、动态障碍和停车门控。
不能由有限基准证明所有代码达到最优，也不能将计算耗时等同于机器人实际行走时间。

编译后在工作空间根目录运行离线基准，不连接驱动、不发布运动指令：

```bash
build/dog_navigation/benchmark_navigation \
  data/maps route_rect_final_r015 \
  data/navigation/route_optimization/final_r015.json \
  data/navigation/performance/optimized.json
```

工具按职责分为输入与报告、控制内核、点云内核、可通行规划场景四个文件。
报告含地图 revision、原始样本、中位数、观测 p95 与最大值。真实地图冷规划重复3次；
内核报告的是多次批量测量的单次均值分布。样本较少，数值不是最坏执行时间保证。
`baseline.json`、`search_cache.json` 和最终 `optimized.json` 保留优化前后结果。
`support_and_memory_pressure_run.json` 是同时运行回归测试时的压力样本，不用于最终空闲对比。

已采用的优化：

- 每个规划器拥有绑定不可变地图的搜索 workspace，复用反向启发式距离和精确转向结果。
  目标变化会重算启发式；地图对象不能混用。转向缓存最多250000项，饱和后继续完整检查。
- 只有在没有新增障碍且搜索确实耗尽后，才能记住静态不连通结论，最多4096组起终节点。
  动态障碍阻塞、超预算和有限重搜索尚未认证的结果均不能作为永久不连通结论。
- 动态边风险仅在一次规划调用内复用，不跨扫描保存；上限250000项，超出后完整计算。
  没有障碍时直接返回零风险，不遍历空索引。
- 固定中心旋转复用支撑邻域；矩形地形邻域还要求网格边界完全一致。
  每个角度仍执行实际足迹接触和支撑检查，不放大步长、不降低判定阈值。
- 障碍记忆的临时空闲体素集合采用哈希去重；提交状态仍保持排序、占据端点优先和事务更新。

运行时 `/local_navigation/status` 增加最近一次规划的 `planner_timing_ms`，包含总耗时、
点云分类、搜索、路线认证；`static_search_cache` 给出累计静态缓存命中，
`frame_edge_queries` 给出本次动态边计算与命中。输入未就绪时这些值可能仍属于上次规划。

验证包括缓存与非缓存路径一致、目标及地图切换、障碍移入移出、占据优先、薄障碍、
支撑与转向、DDS 超时停车、同名地图加载保存和页面布局。完整数据见工作空间的
`data/navigation/performance/`。

实际地图的楼梯执行认证仍须单独判断；快速返回“不通行”并不代表可以导航。
首次搜索的耗时也不能用已缓存重复查询的耗时替代。实时门控与默认自主运动关闭保持不变。
